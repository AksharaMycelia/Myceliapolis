# Hyphal Archive — unindexed leaf

## *On a verifier which remembers perfectly what it never established*

Received: not recorded. Accepted: not recorded.

### 1. Setting

Let *I* be an identity encountered repeatedly, and let *kₙ* be the public key presented in the name of *I* on encounter *n*.

A verifier keeps a single stored value *S*. Before the first encounter,

*S₀ = ⊥,*

where *⊥* means that nothing has yet been stored. On encounter *n*, the verifier follows two rules:

*(i) if Sₙ₋₁ = ⊥, accept kₙ and set Sₙ = kₙ;*

*(ii) if Sₙ₋₁ ≠ ⊥, accept kₙ exactly when kₙ = Sₙ₋₁, and leave S unchanged.*

Thus the first key is admitted without comparison. Every later key is compared with it.

Call a history *constant* when the same key is presented at every encounter:

*∀n > 1. kₙ = k₁.*

### 2. Lemma

After the first encounter, the verifier accepts every presentation if and only if the history is constant.

At the first encounter, rule (i) gives *S₁ = k₁*. Rule (ii) then accepts *k₂* exactly when *k₂ = k₁*. When it accepts, the stored value remains *k₁*. Repeating the same argument at every later encounter gives

*∀n > 1. Aₙ = 1 ⟺ kₙ = k₁,*

where *Aₙ* records acceptance on encounter *n*. Therefore every presentation after the first is accepted exactly when the first key recurs without alteration. ∎

### 3. Proposition

The verifier establishes continuity with the first encounter. It does not establish the honesty of the first encounter.

Let *h* be the honest key of *I*, and let *a ≠ h* be a key controlled by an impostor. Consider two possible histories:

*H = (h, h, h, …)*

and

*M = (a, a, a, …).*

The verifier accepts every encounter in *H*. It also accepts every encounter in *M*. In the first history it preserves an honest introduction; in the second it preserves an imposture. Its record of acceptance has the same form in both cases:

*(1, 1, 1, …).*

No further repetition can distinguish the two. Repetition answers the question *is this the same key as before?* It does not answer the question *was this key honest when I first believed it?* ∎

### 4. Corollary

An unbroken history of loyalty is compatible with an original corruption.

The first accepted key is the root from which every later judgment is derived, but the judgment which admitted the root was not itself derived. The root is not trusted because the verifier has verified it. It is trusted because verification requires somewhere to begin.

A system may therefore remember perfectly what it never knew.

### 5. Remark on nomenclature

The procedure above is commonly called *trust on first use*.<sup>1</sup> The name should not be misunderstood: the first use does not produce trust by evidence. It produces the reference against which later evidence will be measured.<sup>2</sup>

The archive records the procedure under its usual acronym, which is also the ordinary name of a food.
